# TAPD 分析输出规范

## 通用要求

- 全部使用中文输出
- 必须使用 Markdown 格式输出
- 先写结论，再写依据
- 不用表格
- 不直接粘贴原始命令输出
- 使用 `##` 作为一级分节标题
- 汇总和明细使用无序列表
- 需求明细按状态分组

## 推荐结构

## 分析对象

- 名称
- ID
- 当前空间

## 总览

- 用 2 到 4 句话概括迭代下需求推进情况

## 关键汇总

- 需求总数
- 状态分布
- 时间窗口

## 风险与问题

- 优先写需求状态长期停滞、阶段分布失衡、需下钻任务的需求

## 建议动作

- 给 2 到 5 条可执行建议

## 明细

- 按需求状态分组

## Markdown 模板

```md
## 分析对象

- 迭代：xxx
- ID：123
- 空间：xxx

## 总览

一句话结论。
补充一句推进状态判断。

## 关键汇总

- 需求总数：8
- 状态分布：开发中 2，待测试 3，已发布 1，规划中 2
- 时间窗口：2026-04-15 ~ 2026-05-12

## 风险与问题

- 多个需求停留在前置状态，推进节奏不均衡。
- 个别需求需要继续查看任务拆分和负责人情况。

## 建议动作

- 优先确认未进入开发阶段的需求推进计划。
- 对关键需求继续下钻查看任务详情。

## 明细

### 开发中

- 需求 A

### 待测试

- 需求 B

### 规划中

- 需求 C
```
