# TAPD 分析输出规范

## 通用要求

- 全部使用中文输出
- 必须使用 Markdown 格式输出
- 先写结论，再写依据
- 不用表格
- 不直接粘贴原始命令输出
- 使用 `##` 作为一级分节标题
- 汇总和明细使用无序列表
- 任务分组使用独立小节，不要写成一整段

## 推荐结构

## 分析对象

- 名称
- ID
- 当前空间

## 总览

- 用 2 到 4 句话概括当前推进情况

## 关键汇总

- 任务总数
- 状态分布
- 起止时间
- 研发人员
- 总预估工时

## 风险与问题

- 只写真正影响进度和交付判断的问题

## 建议动作

- 给 2 到 5 条可执行建议

## 明细

- 按 `进行中 / 未开始 / 已完成` 分组

## Markdown 模板

```md
## 分析对象

- 需求：xxx
- ID：123
- 空间：xxx

## 总览

一句话结论。
补充一句风险判断。

## 关键汇总

- 任务总数：10
- 状态分布：进行中 2，未开始 6，已完成 2
- 起止时间：2026-04-22 ~ 2026-05-18
- 研发人员：A、B、C
- 总预估工时：12d

## 风险与问题

- 测试任务整体偏后，存在压缩回归时间的风险。
- 未开始任务占比高，且集中在迭代后半段。

## 建议动作

- 优先确认本周要启动的开发任务负责人。
- 提前锁定测试排期，避免开发完成后集中堆积。

## 明细

### 进行中

- 任务 A
- 任务 B

### 未开始

- 任务 C
- 任务 D

### 已完成

- 任务 E
```
