# TAPD 分析输出规范

## 通用要求

- 全部使用中文输出
- 必须使用 Markdown 格式输出
- 先写结论，再写依据
- 不用表格
- 不直接粘贴原始命令输出
- 使用 `##` 作为一级分节标题
- 汇总和明细使用无序列表
- 需求与任务分别分组，不要混在一段里

## 推荐结构

## 分析对象

- 名称
- ID
- 当前空间

## 总览

- 用 2 到 4 句话概括迭代整体健康度

## 关键汇总

- 需求总数
- 任务总数
- 状态分布
- 起止时间
- 研发人员
- 总预估工时

## 风险与问题

- 优先写排期风险、测试滞后、状态堆积、负责人过度集中

## 建议动作

- 给 2 到 5 条可执行建议

## 明细

- 需求与任务分开展示
- 任务明细按 `进行中 / 未开始 / 已完成` 分组

## Markdown 模板

```md
## 分析对象

- 迭代：xxx
- ID：123
- 空间：xxx

## 总览

一句话结论。
补充一句节奏或风险判断。

## 关键汇总

- 需求总数：8
- 任务总数：17
- 状态分布：进行中 1，未开始 8，已完成 8
- 起止时间：2026-04-15 ~ 2026-05-12
- 研发人员：A、B、C
- 总预估工时：12d

## 风险与问题

- 测试任务排期偏后，后段回归压力较大。
- 部分需求仍停留在前置状态，可能影响联调窗口。

## 建议动作

- 优先确认未开始任务的启动时间。
- 对高风险需求继续下钻查看任务详情。

## 明细

### 需求情况

- 需求 A：开发中
- 需求 B：待测试

### 任务情况

#### 进行中

- 任务 A

#### 未开始

- 任务 B

#### 已完成

- 任务 C
```
